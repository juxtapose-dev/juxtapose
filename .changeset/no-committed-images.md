Projects no longer commit snapshot images. The default storage is now `{ "kind": "cache" }`: baseline images live in a git-ignored, hash-keyed cache (`.juxtapose/cache/baselines/<sha256>.webp`), and the repo carries only `juxtapose.manifest.json`, a lockfile holding each story's hash (which decides pass/fail) and its approved structure inline (one element per line, stories sorted by id, so an approval diff shows what moved; the file stays `"version": 1`, which an older jux reads as the same hashes). On a merge conflict, don't hand-merge it: take either side and re-run `jux approve --story <id>`. `.juxtapose/` is entirely machine-local and ignored with one line. A failing story whose image is not in the cache is reported by hash and structure ("baseline image not available (not in cache); structure diff only") instead of erroring, in run output, the PR comment, the handoff, the HTML report and the panel. A passing run keeps its capture in the cache; `jux run` never writes the manifest. `jux init` writes the `.gitignore` entries, and the new `jux doctor` lists tracked images and prints the migration. `docs/ci.md` has a GitHub Actions snippet that saves and restores the cache. The cache is not pruned yet (see #114). A cache or tmp directory that is a symlink is never written to or swept. The cache's `dir` is now validated: a relative path inside the project with no `..`, absolute or UNC path, glob characters, control characters or leading `-`. A `git` or `fs` `dir` is unchanged (any path, including outside the project), apart from refusing a leading `-` and control characters. A refused value exits 2.

Migration. Projects with `storage.kind: "git"` (or `"fs"`) set explicitly are unchanged. Projects with no `storage` key and images committed under `.juxtapose/baselines/` keep working: jux still reads those images (when they match the manifest hash) and writes new ones to the cache. To move over, run `jux doctor` and follow what it prints: `jux run --all` first (it copies each image that matches the manifest into the cache, which matters because the commit that untracks the images deletes them from every other clone), then `git rm --cached -- ':(glob).juxtapose/baselines/*.webp'`, the `.gitignore` line `.juxtapose/`, and a commit. Teammates and CI then have no images until their own run or a restored CI cache fills the cache, and report structure only until then. The old per-story `.structure.json.gz` files are folded into the manifest by `jux doctor --fix` (no capture, no approval); doctor then prints the commands to untrack them. To keep committing images, set `"storage": { "kind": "git" }`.
