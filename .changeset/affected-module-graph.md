`jux run --since` now captures only the stories a changed component reaches, instead of every story (#200). Vite's build manifest lists chunks, not the modules bundled into them, so a shared component never appeared in it and almost every UI edit fell back to a full run. The Storybook addon now adds a Vite plugin to `storybook build` that records every source module and its imports to `.vite/juxtapose-modules.json`; the analysis walks that. Ladle and other Vite workbenches add `juxtaposeModuleGraph()` from the new `@juxtapose/core/vite` export to their `vite.config.js`. Rebuild once after upgrading, and before each `--since` run.

The graph follows more than JavaScript imports: CSS `@import` and `url()`, Sass `@use`/`@forward`, CSS-modules `composes`, and `new URL(…, import.meta.url)`. Anything it cannot place still captures everything, and the printed reason names the file: a changed file the build never saw (`unmapped-change`, even beside mapped files), a module that runs for every story such as the preview, including when each story imports it (`shared-entry-changed`), a changed stylesheet or asset in a build with references the plugin could not follow, web workers or Tailwind (`asset-changed`), a source modified after the build started (`stale-graph`), a graph built from another root (`graph-root-mismatch`), and any `--origin` run (`origin-run`). Docs pages (`.mdx`) no longer force a full run. The plugin never fails a build: on an error it warns and writes no graph. A webpack Storybook build is told narrowing is not available instead of being asked to add a Vite plugin. Also fixed: git's repository-relative paths are mapped to project paths, so affected-only runs work when the workbench is below the repository root (#96), and a project-level `tsconfig.json`, lockfile or `.storybook` there now escalates.
