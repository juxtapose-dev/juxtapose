# Startup context and explicit candidate measurements

Local research only; no source-prefill or candidate-probe API/default is added.
The saved-artifact handoff fix is a separate verified product change.

## Source prefill did not establish a reliable win

Four Sol 6.1 medium trials in C T T C order compare the same small planner
repair with and without a 3353-byte snapshot of five public editable files.
Both arms receive identical source access/map, images, MCP tools, exact run
handle and bounded-discovery instructions. The first pair reduces model calls
3→2 and process time 17.673→12.896s, with counted usage 6575→6477. The reverse
pair needs typography corrections: candidate 5 calls/27.592s/8475 counted;
control 5 calls/28.877s/25322 last-reported counted stops at the reserve gate.
All independent image/behavior checks pass, but the capped model session is
incomplete. No pooled saving is valid, and cache behavior differs substantially.

All four outcomes remain recorded; no replacement trial runs. Do not add a
default source-prefill feature or cherry-pick the first pair. The candidate's
initial 32/28px font guess later becomes 30/26px, so target-value uncertainty
creates additional edit/verification phases even without source reads.

Artifacts: `juxtapose-experiments/iteration-billing/startup-source-context-v1`.
The study spends 46849 last-reported counted tokens, excluding 227328 cached
input; the stopped arm may lack final billing telemetry.

## Candidate capture is an offline lead

A separate no-model harness tests seven caller-specified values of an existing
CSS variable at two viewports through native captures. It uses only public
current source and reference PNGs, injecting temporary CSS in served responses
without editing the source. Both batches find unique zero-Pixelmatch candidates
at 30px desktop/26px mobile; decoded RGBA is also identical to each reference.
All 14 candidate hashes/counts repeat across private browser launches.

Each batch costs about 1.42–1.43s including CLI/private browser startup,
14 captures and per-candidate decode/compare. Initial reference decoding and
controller/source loading are excluded. The resulting measured packet is
624 bytes. This is a candidate search, not automatic CSS diagnosis or a
measured reduction in agent time. It uses more capture work than a correct
first guess; test on demand for uncertainty or failed edits. No production
API, analysis module, native dependency or acceptance change is introduced.
