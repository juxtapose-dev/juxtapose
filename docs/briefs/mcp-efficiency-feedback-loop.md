# MCP efficiency guidance and benchmark feedback

Status: local branch, no publish or workflow savings claim.

The contact hypothesis pilot completes at equal quality but saves only one
call and 6.3% local time; both agents make the same wrong first edit. The
treatment probes only after that failure. A separate historical audit finds
no exact repeated saved-evidence request candidates in four selected traces.
This motivates better evidence timing and selection, not forced probes or
an assumption that duplicate requests dominate.

## Product changes

Keep shared initialization small because a real client repeated it on every
tool. Guide clients to reuse saved evidence, resolve only missing facts and
prefer MCP measurements to images. A passing hint discourages another report
or reference call. Capture/reference errors direct attention to incompatible
inputs rather than a visual edit. On mismatch, ask for focused geometry first
only when needed; full ledgers and local pixel analysis need a specific missing
fact. Focused responses add a typed status-specific `next` instruction.
When a saved changed region exists, `cropRequest` provides valid crop arguments
and `cropRegion` identifies its changed-pixel bounds. This is only the largest
region, not a claim that it answers every remaining question. Missing IDs do
not become fabricated crop requests.

These are conditional instructions. Direct edits remain appropriate when
source and measurements determine the value. No public hypothesis probe,
automatic CSS diagnosis, acceptance change or image-tool prohibition is added.

## Test-agent feedback

The experiments harness adds opt-in feedback to the existing final response,
identically in both arms: at most three encountered-friction reports and600
UTF-8 bytes. Empty is normal. Reports identify a needed observable, actual
workaround and visible qualified tool reference with minimal arguments. A
guess/no-workaround may have no tool witness. No additional feedback tool or
model turn is required; output overhead remains included in usage.

The collector matches visible references against completed direct MCP/command
events, retaining server identity, event IDs and hashes. Nested/local actions
may be missing; unmatched reports are unverified rather than contradicted.
Links do not establish necessity, missing capabilities or savings. Suggestions
remain unreviewed until checked against actual returned evidence and a small
acceptance gate. Never pass accumulated complaints to held-out agents.

`run_feedback_trial` connects the collector to the guarded executor for future
controllers. It requires the exact suffix to be present in the frozen prompt,
saves an audit automatically and preserves validity, usage and stop policy.
Missing or malformed feedback cannot cause a repeat. Eight unit checks cover
these mechanics. A live single-call routing screen collects a valid empty
report in the existing final response. No repair agent has supplied feedback
under this hook yet. Historical absence is explicitly expected; no opinions
are synthesized.

Artifacts and the reviewed next-experiment backlog live in
`juxtapose-experiments/iteration-billing/agent-feedback-loop-v2`. The relevant
efficiency gate contains both geometry-sufficient and appearance-uncertain
cases, checks equal exact visual/behavior quality first, then failed cycles,
calls, captures, time and usage categories. Earlier probe uptake or smaller
image counts alone cannot establish a win.
