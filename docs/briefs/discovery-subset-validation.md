# Selected-story discovery validation

This updates draft PR #228 on current main (`7239da1`) without changing
which stories affected analysis considers safe to skip. Parameter discovery
loads only a narrowed selection; unknown/stale graph cases retain the existing
full-capture fallback.

## Full selections and variants

The original patch compared affected **base story** count with the
variant-expanded capture count. With project variants, a full selection was
therefore sent as an explicit list rather than omitted, contradicting the
whole-store/cache-sharing contract. Compare against enumerated base stories
instead. An empty explicit-story list also means no explicit filter.

CLI regression coverage uses real temporary Git repositories, real graph
validation and discovery/cache plumbing; only browser capture is replaced.
It checks full selection with project variants, changed-component selection
and its variants, stale/unmapped/config fallbacks, unchanged early exit, and
explicit variant selection. Reverting the count fix makes four cases fail.

## Real Storybook 10 discovery

Serial Chrome checks used existing builds/dependencies, no package install.
Both `preview.loadStory` and `store.loadStory` existed in all three builds.
Selected parameters matched the same IDs from whole-store extraction.

| Build                     | Version | Selected / stories | Subset ms | Full ms |
| ------------------------- | ------- | -----------------: | --------: | ------: |
| Isolated two-file fixture | 10.6.0  |              1 / 2 |       109 |      90 |
| Chakra                    | 10.4.2  |          3 / 1,227 |       294 |     388 |
| Primer                    | 10.5.10 |          3 / 1,102 |       143 |     373 |

These are **single observations**, with subset followed by full in separate
contexts of one browser. They are compatibility checks, not controlled speedup
measurements. The small fixture checks nonempty inherited viewport and
story-local variant parameters. Chakra/Primer do not declare juxtapose
parameters for the selected IDs, so their check establishes successful
per-story loading, not parameter inheritance coverage.

## Real CLI --since checks

An isolated Storybook 10.6 fixture contains A and B stories, project dark
variants, and an A-only mobile variant. It has a real Git history and a
fresh module graph generated by the current Vite plugin. A comment-only
component edit followed by a rebuild exercises narrowing without an intended
pixel change. All runs use concurrency 3, no daemon and temporary state.

| Case                                           |              Captures | Reason         |
| ---------------------------------------------- | --------------------: | -------------- |
| Initial `--all`                                |                     5 | no-baseline    |
| Unchanged `--since HEAD`                       |                     0 | no-changes     |
| Component edit + rebuild, `--since HEAD`       | 3 (A + dark + mobile) | graph-walk     |
| `--all` after subset                           |                     5 | no-baseline    |
| `--story a--default__mobile`                   |                     1 | requested      |
| Source edit without rebuilding, `--since HEAD` |                     5 | stale-graph    |
| Config edit, `--since HEAD`                    |                     5 | config-changed |

All expected IDs and reasons matched, with zero capture errors. This fixture
was deliberately unapproved: captures have `new` status and exit 1; the
unchanged run exits 0. These checks establish selection/fallback behavior,
not approved-baseline parity or repeated rendering determinism.

[CLI evidence](discovery-subset-since-validation.json). Temporary source/build:
`/tmp/jux-discovery-sb10`; raw logs/reports: `/tmp/jux-discovery-since-evidence`
and that fixture's `.juxtapose/runs`. Discovery harness:
`/tmp/jux-discovery-browser.mjs`.

## Remaining gates

- Storybook 9 remains unverified. No installed local fixture was found. The
  suggested official `release-9-0--storybookjs.netlify.app` deployment returned
  HTTP 404; that is not a compatibility result. Keep the PR draft until a
  real Storybook 9 build is tested, or explicitly scope support otherwise.
- Repeat cold-cache subset/full comparisons before claiming a speedup.
- Discovery currently keeps one cache entry: alternating distinct selections
  evicts it. A full-map cache that can safely satisfy subsets is separate work.
- CSS/public assets, graph gaps, stale builds and unknown changes must retain
  conservative affected-analysis fallbacks. This patch does not weaken them.
